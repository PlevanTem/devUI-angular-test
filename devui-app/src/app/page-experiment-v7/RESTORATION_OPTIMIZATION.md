# 测试用例配置页 (V7) 还原效果优化方案

针对「顶部导航栏、侧边栏图标、按钮、表单、表格」识别漏/不准的问题，从**规范层**和**实现层**两方面做优化。

---

## 一、当前还原与设计稿的差异（问题清单）

| 区域 | 设计稿要点 | 当前实现 | 差距 |
|------|------------|----------|------|
| **顶部导航** | 中部导航带图标（首页=房子、工作台=桌子、效能看板=图表、服务=文件夹+下拉、开源镜像站=窗口）；右侧新功能红按钮、加号/搜索/铃铛/问号/头像+下拉 | 导航仅文字无图标；区域「华北-北京四」为纯文本无下拉；头像无下拉箭头 | 导航图标缺失、区域未做成下拉、头像无 chevron |
| **侧边栏** | 项目设置旁有搜索图标；每项左侧有独立图标（齿轮/文件夹/分支/代码/流水线/锤子/火箭/发布/图表/烧瓶/清单/剪贴板/机器人/省略号/书/文档/库/数据库/盾牌），右侧箭头；当前项蓝底白字；底部齿轮+箭头 | 仅有文字，无每项图标、无右侧箭头、无项目设置旁搜索 | 整块图标与箭头缺失 |
| **按钮** | 新功能=红色矩形；添加=「+ 添加」；保存=主按钮蓝；取消=次要灰 | 已用 bsStyle 区分，视觉可再贴近设计（尺寸、圆角） | 小调即可 |
| **表单** | Toggle 开=蓝、关=灰；输入框聚焦有蓝色边框 | 已用 d-toggle/d-text-input，聚焦态依赖组件库默认 | 可加强 focus 可见度 |
| **表格** | 表头灰底、单元格内输入框、删除为垃圾桶图标；整体为表格线框 | 已用原生 table + d-text-input + d-icon 删除 | 表头/边框/行高可再贴近 |
| **Toast** | 绿色背景、白色勾、Summary 标题、可关闭 | 当前为白底+成功图标，未用绿色背景 | 需改为成功色背景 |

## 二、优化方向（分层）

### 1. 规范层：让「识别」更准、更全

- **多模态 Spec 细化**  
  - 在 `multimodal_spec` 的 `region_decomposition` 和 `component_specification` 中**显式列出**：  
    导航每项文案+图标语义（如 首页=home）、侧栏每项文案+图标语义、按钮类型（主要/次要/危险）、表单控件类型（Toggle/Input）、表格列与操作（删除图标）。  
  - 便于生成代码时直接映射到 DevUI 组件与图标名。

- **双源对比后做「合并清单」**  
  - 解析器 OCR 提供文案与大致区域；多模态提供组件类型与图标语义。  
  - 对比报告产出「最终清单」：每个区块的文案 + 组件类型 + 推荐图标（如 `icon-home`），再交给代码生成，减少漏识别和误用组件。

- **图标映射表**  
  - 在 Skill 或项目内维护「设计稿常见语义 → DevUI icon 名」映射（如 首页→icon-home, 工作台→icon-menu, 设置→icon-setting），生成代码时查表填充，避免侧栏/导航图标漏写或写错。

### 2. 实现层：在 V7 上直接补齐

- **顶部导航**  
  - 为「首页/工作台/效能看板/服务/开源镜像站」配 `d-icon`（icon-home, icon-menu, icon-standard 等），服务后加 `icon-chevron-down`。  
  - 「华北-北京四」改为 `d-select` 或保持文本但样式像下拉。  
  - 头像右侧加 `d-icon icon-chevron-down`。

- **侧边栏**  
  - 为每项配置 `icon` 字段（如 通用配置=icon-setting, 代码托管=icon-git），模板中 `d-icon [icon]="item.icon"`。  
  - 每项右侧加 `d-icon icon-chevron-right`。  
  - 项目设置右侧加搜索图标。  
  - 当前项样式：蓝底白字（已有，可微调对比度）。

- **Toast**  
  - 使用成功色背景（如 `var(--devui-success)` 或浅绿），白字，勾图标白色，与设计稿一致。

- **表格与表单**  
  - 表头背景、边框、行高用 Design Token 统一；为 `d-text-input` 增加 focus 时的边框/阴影类（或依赖库默认），确保聚焦态明显。

### 3. 流程层：后续图生 UI 的固定步骤

1. **出图 → 解析器**：得到区域 + OCR 文案。  
2. **出图 → 多模态**：得到区域 + 组件类型 + 图标语义 + 按钮/表单类型。  
3. **双源对比**：跑 `compare_parser_vs_multimodal.py`，人工修正冲突。  
4. **合并清单**：输出「区域 + 文案 + 组件类型 + 推荐图标」的最终 Spec。  
5. **代码生成**：按 Hybrid 规范 + 注释规范 + **图标映射表** 生成模板与样式；对「导航/侧栏/按钮/表单/表格」逐项对照合并清单，避免漏写图标或错用组件。
