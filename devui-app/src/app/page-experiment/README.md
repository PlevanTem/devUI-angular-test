# 页面级还原实验记录

## 实验目标

对比两种页面级实现方案：
1. **像素级还原方案**：100%还原页面视觉效果
2. **DevUI规范方案**：使用DevUI组件库和设计令牌

## 实验日期

2026-02-07

## ⚠️ 版本兼容性说明

**重要**: 本项目使用 Angular 21.1.3，而 DevUI 18.0.0 期望 Angular ^18.0.0。

由于版本不匹配，`d-form` 容器组件无法在 standalone 模式下正常工作。我们采用了混合方案：
- ✅ 使用原生 `<form>` 元素作为容器
- ✅ 使用 DevUI 表单子组件（`d-form-item`, `d-form-label`, `d-form-control`）
- ✅ 通过 CSS 模拟 DevUI 表单布局

详细说明请查看项目根目录的 [VERSION_COMPATIBILITY.md](../../VERSION_COMPATIBILITY.md)

## 页面结构分析

### 1. 页面头部
- **标题**："新建实例"
- **图标**：云朵/闪电图标，浅蓝色

### 2. 左侧导航侧边栏
- **步骤导航**：
  - 基础配置（已完成，蓝色勾选图标）
  - 工程配置（当前激活，蓝色左侧边框）
- **连接线**：步骤之间的垂直连接线

### 3. 主内容区域
- **表单区域**：
  - 来源选择（单选按钮组）：样例工程/私有仓库/不创建工程
  - 工程名称输入框
  - 工程模板搜索框（带搜索图标）
- **模板卡片网格**：
  - 3列网格布局
  - 每个卡片包含：标题、描述、标签
  - 选中状态：蓝色边框 + 右上角选中指示器

### 4. 页面底部
- **费用显示**：左侧显示配置费用
- **操作按钮**：上一步、取消、确定

## 实现方案对比

### 方案一：像素级还原

#### 技术选型
- 原生HTML元素
- 自定义CSS样式
- Flexbox/Grid布局
- 自定义SVG图标

#### 实现要点
- 所有颜色值硬编码
- 精确的像素级间距
- 自定义表单样式
- 自定义卡片样式
- 自定义按钮样式

#### 代码量
- HTML: ~150行
- CSS: ~500行
- TypeScript: ~100行

### 方案二：DevUI规范

#### 技术选型
- DevUI Form组件
- DevUI Card组件
- DevUI Radio组件
- DevUI Button组件
- DevUI Tag组件
- DevUI Icon组件

#### 实现要点
- 使用`d-form`、`d-form-item`、`d-form-label`、`d-form-control`
- 使用`d-text-input`、`d-radio`
- 使用`d-card`展示模板卡片
- 使用`d-tag`展示标签
- 使用`d-button`实现操作按钮
- 使用DevUI设计令牌

#### 代码量
- HTML: ~120行
- CSS: ~200行
- TypeScript: ~100行

## 关键发现

### 方案一（像素级还原）的优势
1. ✅ **精确还原**：能够100%还原设计稿
2. ✅ **完全控制**：对每个细节都有完全控制权
3. ✅ **独立性**：不依赖组件库

### 方案一（像素级还原）的劣势
1. ❌ **代码量大**：需要编写大量CSS
2. ❌ **维护成本高**：需要手动维护所有样式
3. ❌ **功能缺失**：表单验证、可访问性等需要手动实现
4. ❌ **不一致性风险**：可能与整体设计系统不一致

### 方案二（DevUI规范）的优势
1. ✅ **代码简洁**：使用组件库，代码量少
2. ✅ **功能完整**：自动获得表单验证、可访问性等能力
3. ✅ **易于维护**：跟随组件库更新自动维护
4. ✅ **设计一致性**：符合整体设计规范

### 方案二（DevUI规范）的劣势
1. ❌ **灵活性较低**：受限于组件库的能力
2. ❌ **可能需要调整**：某些特殊设计可能需要妥协

## 技术细节对比

### 表单实现

| 元素 | 方案一 | 方案二 |
|------|--------|--------|
| 表单容器 | `<form>` + 自定义样式 | `<d-form>` |
| 表单项 | `<div>` + 自定义样式 | `<d-form-item>` |
| 标签 | `<label>` + 自定义样式 | `<d-form-label>` |
| 输入框 | `<input>` + 自定义样式 | `<d-text-input>` |
| 单选按钮 | `<input type="radio">` + 自定义样式 | `<d-radio>` |

### 卡片实现

| 元素 | 方案一 | 方案二 |
|------|--------|--------|
| 卡片容器 | `<div>` + 自定义样式 | `<d-card>` |
| 卡片标题 | `<h2>` + 自定义样式 | `<d-card-title>` |
| 卡片内容 | `<div>` + 自定义样式 | `<d-card-content>` |

| 主文本 | #333333 | text-primary (#1D2129) |
| 次要文本 | #666666 | text-secondary (#4E5969) |
| 主色调 | #165DFF | primary (#165DFF) |
| 危险色 | #F53F3F | danger (#F53F3F) |

## 最佳实践建议

1. **优先使用DevUI组件库**
   - 大多数情况下，组件库能够满足需求
   - 保持设计一致性，降低维护成本

2. **在必要时进行定制**
   - 使用CSS变量或设计令牌进行定制
   - 避免完全重写组件样式

3. **保持一致性**
   - 即使使用自定义样式，也要遵循设计令牌
   - 确保与整体设计系统保持一致
